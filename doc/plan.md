## 0. 現在地と次の一手

2026-10-16 時点。

**入っているもの**

- Y8960 の拡張 OPL2 部 `OPL2EX` と拡張 OPLL 部 `OPLLEX`（§3.1、§3.2）
- Y8960 の `SSGS`（§3.6）
- Y8960 の仕様書（2026-10-15 更新の xlsx。§2）への追随（§3.10）。`SSGS` はレジスタ配置が
  変わり、チャンネルごとの音量と 8bit の定位を持つ。`clock` は SSG の動作クロック。`OPLLEX` は
  `50h`-`58h` の定位を持つ。`OPL2EX` は SP-OFF を持たない。定位の則は等パワー（ユーザー決定）
- FmEngineApi の外部メモリ（任意エクスポート。列挙の 2 関数と `FmEngine_SetMemory`、
  `FmEngine_SetMemoryEx`）。名前で指定する。`Y8950` は `ADPCM_B` / `ADPCM_B_ROMMODE`、
  `OPL2EX` は `ADPCM_B`。`FmEngine_SetMemoryEx` は `OPL2EX` が仕様どおり、`Y8950` は
  制限付き（§3.7）
- FmEngineApi の部位ゲイン（任意エクスポート 4 関数）。名前で指定する。部位を持つのは
  `OPLL` / `OPLLP` / `OPLLX` / `VRC7`（`MELODY` / `RHYTHM`。§3.3）。`OPLLEX` は部位を
  出さない（2026-10-03 ユーザー決定。§6.1）
- `FmEngine_AddChip` は `clock` = 0 を受け付けない。既定のクロックは持たない（§3.8）
- `FmEngine_GetNativeRate` はエクスポートしない（仕様から外れた。§3.9）
- ステレオ出力のレート変換の位相ずれは、4 つのコアがそれぞれ自分で揃える（§3.4）。
  emu2413（v1.6.4）と emu8950（v1.2.3）は上流の修正。フォーク（`OPL2EX` / `OPLLEX`）は
  それぞれの変換器を写した。エンジン側の回避策は取り除いた（§5.9〜§5.11）
- emu2413 の submodule は v1.6.4（`a1d5120`）。`OPLLEX` のフォークにも同じ変換器を入れ、
  素の `OPLL` と揃えた（§3.1、§5.11）
- emu8950 の submodule は v1.2.3（`f82a22e`）。ADPCM は再生が止まると 0 を出す（v1.2.2 から）。
  `OPL2EX` のフォークには v1.2.2 の ADPCM の 2 箇所と v1.2.3 のレート変換器を入れ、`Y8950` /
  `OPL2` と揃えた（§3.2、§5.7、§5.10）
- `tests/api_test.cpp`（111 項目）と CTest への登録

**仕様への追随**: FMEngineTest `831947d` まで（§2）。`src/FmEngineApi.h` は同じコミットの
`include/FmEngineApi.h` の写しで、エンジン側に仮の宣言は残っていない。

**番号で指定する形の呼び出し側と組み合わせない。** `0c22d67` より前のヘッダでビルドした

  `data` に書き込まない、`clock` = 0 の廃止、部位と外部メモリを名前で指定）に追随する

## 3. 仕様

### 3.1 OPLLEX

**コア**: `src/y8960/Y8960OpllCore.{c,h}`。emu2413 v1.5.9 のフォークで、公開記号は
`OPLL*` → `Y8960OPLL*` に改名してある（素の emu2413 と同じバイナリに入るため）。

素の emu2413 v1.5.9 との差（**確認済み**: 改名を戻して、submodule が `11676f6` だったときの
`emu2413.c/.h` と diff を取った。そのときの submodule の作業ツリーは記録コミット `11676f6` と
`CMakeLists.txt` だけが違い、ソースは同一だった）:

| 差 | 内容 |
|---|---|
| 音色表 4 面 | `patch[19*2]` → `patch[4][19*2]`。バンク順は 0 OPLL / 1 OPLL-X / 2 OPLL-P / 3 VRC7 |
| チャンネル別バンク | `patch_bank[9]`。`set_patch()` がこれを見て向け先を選ぶ |
| バンクレジスタ | `40h`-`48h` の b1:b0。`reg[]` を `0x49` 語に広げた（2026-10-16 に定位で `0x59` 語） |
| 定位レジスタ | `50h`-`58h`（2026-10-16。下の「定位」）。この行は 2026-10-16 に足したもので、上の diff の確認には入っていない |
| ユーザー音色 | `user_patch[2]`。バンクに属さずチップに 1 組 |
| 関数の引数 | `resetPatch()` は全バンクを読み直す。`setPatch` / `copyPatch` はバンクを取る |

**emu2413 v1.6.3 から取り込んだもの**（2026-10-08）: `Y8960OPLL_calcStereo` が L と R を同じ
補間位置で取る（上流の PR #21 と同じ 2 行。§3.4）。v1.6.4 の変換器に置き換わり、この 2 行は
無くなった（変換器が L と R に同じ位相を渡す）。

**emu2413 v1.6.4 から取り込んだもの**（2026-10-16。§6.8 の決着）: 上流 `83254be..a1d5120` の
`emu2413.c` / `emu2413.h` の差分を、記号を改名して当てた。当たらなかったのは版の表記と
`OPLL_load_state` の 2 か所で、フォークに無いので外した。入ったのは、レート変換器（固定小数点、
位相を `out_time` から毎回求めて丸める、リングバッファ）、整数の出力タイミング、`pan_fine` の
4.12 固定小数点（**確認済み**: §5.11）。

v1.6.0〜v1.6.2 の変更（状態の保存・復元、リセットで消す状態の追加、テーブルの縮小、
`OPLL_calc` の高速化）は取り込んでいない。取り込んでいないフォークのユーザー音色が、
取り込んだ素の `OPLL` とビット一致する（**確認済み**: §5.1 の試験）。

**定位**（2026-10-16。§3.10）: `50h`-`58h` が ch0-8 の 8bit の定位。則は §3.10。コアは
emu2413 がもともと持つ `pan_fine` を、レジスタの書き込みで決める（`set_channel_pan`）。
リズムの音は、使うスロットのチャンネルの定位に従う（BD は ch6、HH と SD は ch7、TOM と CYM は
ch8）。仕様書はリズムの定位を書いていない（**推測**: YM2413 のリズムは ch6-8 のスロットで
作られるので、そのチャンネルの定位に従うと読んだ）。リセットで 9 個とも 128（中央）にする。
`reg[]` は `0x59` 語に広げた。`pan`（L / R の出し分けのビット）は使わず、3 のまま。

**エンジン側**: `Y8960OPLL_new()` が音色の読み込みとリセットまで済ませる。出力は
`Y8960OPLL_calcStereo` の L / R をそのまま使う。部位は出さない（2026-10-03 ユーザー決定。§6.1）。
2026-10-16 まではメロディを L、リズムを R に振り分けて取り出し、等倍で混ぜ直していた（§6.1）。

### 3.2 OPL2EX

**コア**: `src/y8960/Y8960Opl2exCore.{c,h}`、`Y8960Opl2exAdpcm.{c,h}`。emu8950 v1.1.4 の
フォークで、公開記号は `OPL*` → `Y8960OPL*` に改名してある。

素の emu8950 v1.1.4 との差（**確認済み**: 改名を戻して、submodule が `c27078c` だったときの
4 ファイルと diff を取った。そのときの submodule の作業ツリーは記録コミット `c27078c` と
`CMakeLists.txt` だけが違った）:

| 差 | 内容 | 理由 |
|---|---|---|
| チップ種別を削除 | ADPCM を常に持ち、`E0h`-`F5h` の波形選択を常に `01h` の b5 で許す | emu8950 は ADPCM を Y8950 に、波形選択を YM3812 にしか与えない |
| ADPCM の ROM を削除 | `08h` の b0 を無視。アドレス単位は b1 だけで決まる（0: 4 バイト、1: 32 バイト。emu8950 の RAM256K / RAM64K と同じ） | Y8960 の ADPCM の後ろには SRAM しか無い（両フォークの文書。2026-09-12 のユーザー回答が出典） |
| サンプルメモリを外に出す | `Y8960OPL_setADPCMMemoryMap()` で割り当ての表（`base` / `size` / ブロック / 書けるか）を渡す。どの割り当てにも入らない番地の読みは 0、書き込みは捨てる。書けない割り当てへの書き込みも捨てる | 実機は 2 回路で 256KB を分け合い、分け方が 4 状態ある。`FmEngine_SetMemoryEx` の割り当てをそのまま表せる |
| `emuadpcm.c` の外部記号 | `FILE *fp` を削除、`decode_*_address` を `static` に | 素の emu8950 と同じバイナリに入るため |

**emu8950 v1.2.2 から取り込んだもの**（2026-10-08。ユーザーの指示）:

- ADPCM の止まり方の 2 箇所。`Y8960OPL_ADPCM_calc` は `play_start` が 0 の間 0 を返し、`07h` への
  START の無い書き込みは `play_start` を 0 にする。上流の PR #12・#13 と同じ行で、`Y8950` と
  止まり方が揃う（**確認済み**: §5.7）
- `Y8960OPL_calcStereo` が L と R を同じ補間位置で取る（上流の PR #10 と同じ 2 行。§3.4、§5.9）。
  v1.2.3 の変換器に置き換わり、この 2 行は無くなった（変換器が L と R に同じ位相を渡す）

**emu8950 v1.2.3 から取り込んだもの**（2026-10-16。§6.8 の決着）:

- 上流 `30e89e2..f82a22e` の `emu8950.c` / `emu8950.h` の差分を、記号を改名して当てた。
  当たらなかったのは版の表記と `OPL_load_state` の 2 か所で、フォークに無いので外した。
  入ったのは、レート変換器（固定小数点、位相を `out_time` から毎回求めて丸める、リング
  バッファ）、出力のタイミング（`out_step = clk`、`inp_step = rate * 72`。内部レートが整数に
  切り捨てられなくなる）、`pan_fine` の 4.12 固定小数点（**確認済み**: §5.10）

**v1.2.0〜v1.2.3 から取り込んでいないもの**（フォークは v1.1.4 のまま）:

**Y8960 の仕様書（2026-10-15）で変えたもの**（§3.10）: `07h` の b3（SP-OFF）を無視する。
仕様書が「SPOFF 廃止」としている。`Y8960OPL_ADPCM_calc` の先頭の 2 行を外した。

**仕様書で廃止とされ、もともと効いていなかったもの**（**確認済み(読解)**。試験もある）:
`05h` `06h`（キーボード）はフォークの `writeReg` がどこにも渡さない。`0Dh` `0Eh`（プリスケール）は
ADPCM の `reg[]` に置くだけ。`15h`-`1Ah`（DA / AD、I/O、PCM）は `07h`-`12h` の外なので ADPCM に
渡らない。

**変えていないもの**（emu8950 のまま）: 波形選択の効き方（後述）、64K モード、ステータス。
`08h` の b0（ROM）は仕様書で廃止とされずに残っているが、無視したまま（2026-10-16 ユーザー決定。
§6.9）。

**エンジン側**: チップ 1 個ごとに 256KB の `std::vector` を持ち、`FmEngine_SetMemory` の `ADPCM_B`
はそこへ先頭から複製する（256KB を超える分は捨てる）。`FmEngine_SetMemoryEx` の割り当てが
無い間は、この 256KB を 0 番地から 1 つの割り当てとしてコアに渡す（§3.7）。

**両フォーク（openMSX_Y8960 / blueMSX-plus_Y8960）との違い**（**確認済み(読解)**:
本リポジトリ側はコード。両フォーク側は openMSX_Y8960 の `Y8960OPL2.cc` の
`updateWaveTables` と `0xe0` の分岐、および両フォークの `implementation-plan.md`）:

| 点 | 本リポジトリ（emu8950 のまま） | 両フォーク（openMSX の Y8950 由来） |
|---|---|---|
| `01h` の b5 が 0 の間 | `E0h`-`F5h` の書き込みを捨てる。b5 を 0 にする前に選んであった波形は残る | `E0h`-`F5h` の書き込みは憶えるが、全スロットがサインで鳴る。b5 を 1 にすると憶えた波形になる |
| リズム用スロット | 波形選択が効く | サインのまま |
| サンプル RAM | `SetMemory` ならチップごとに 256KB。`SetMemoryEx` の RAM で共有・分割・片寄せを表せる（§3.7） | 2 回路で 1 つの 256KB を共有（起動時） |

前の 2 つは実機（Y8960 の OPL2 は jtopl2）で決まる。§6.3。

**両フォークの文書と実装の食い違い**（**確認済み(読解)**）: どちらの文書も「`07h` の b3
（SP-OFF）を落とした」と書くが、両方の ADPCM はいまも b3 で無音になる

2026-10-16 から本リポジトリは b3 を無視するので、振る舞いは両フォークの文書と仕様書に揃い、
両フォークの実装とは食い違う。

### 3.4 レート変換の位相合わせ

**事実**（**確認済み**）: emu2413 と emu8950 のレート変換器（`*_RateConv_getData`）は、
補間位置を決める `timer` を全チャンネルで共有し、呼ぶたびに `f_ratio` だけ進める。
`*_calcStereo` は 1 出力サンプルにつき L と R で 2 回呼ぶので、L と R が別々の、どちらも
誤った位置で補間される。これは emu8950 v1.1.4 / emu2413 v1.5.9 までの作りで、emu8950 は
v1.2.2、emu2413 は v1.6.3 で、`*_calcStereo` が R の前に `timer` を戻すようになった。
`src/y8960` のフォーク 2 つは直る前の版から分かれたので、同じ 2 行を入れてある。

- 計測: emu2413 単体で、48kHz、メロディ 1 音 + リズム 5 音、中央定位。素の
  `OPLL_calcStereo` は |L−R| が最大 10129 LSB（ピーク 17401）、L と mono の `OPLL_calc` の
  差が最大 10298 LSB。timer を 1 出力サンプルにつき 1 回だけ進めると、L = R = mono が
  ビット一致した
- コードの所在: emu2413 `emu2413.c` の `OPLL_RateConv_getData` / `OPLL_calcStereo`、
  emu8950 `emu8950.c` の `OPL_RateConv_getData` / `OPL_calcStereo`
  （**確認済み(読解)**。emu8950 側は同じ形のコード）

**いまの対処**: 4 つのコアがそれぞれ自分の `*_calcStereo` の中で揃える。エンジンは各コアの
`*_calcStereo` をそのまま呼び、コアの内部には触らない。

- 2026-10-08 から: 素の emu2413 / emu8950 は上流の修正、フォーク 2 つは同じ 2 行
  （**確認済み**: エンジンで揃えていた版と出力がビット一致。§5.9）
- 2026-10-16 から: emu2413 v1.6.4 / emu8950 v1.2.3 の変換器は、1 出力サンプルにつき位相を
  `out_time` から 1 回求め、L と R に同じ位相を渡す。`timer` を戻す 2 行は無くなった。フォーク
  2 つも同じ変換器を写した（**確認済み**: 4 つのコアとも L == R == mono。§5.10、§5.11）

**以前の対処**（2026-10-08 まで）: `src/DSAemuEngine.cpp` の `calcStereoAligned()`。呼ぶ前に
timer を 1 サンプルぶん進めて置き、呼び出しの間だけ `f_ratio` を 0 にして、全 OPL / OPLL 系
チップに掛けていた。上流が直る前に、submodule を改造せずに揃えるための回避策だった。
4 つのコアがすべて自分で揃えるようになったので取り除いた。

**影響**: OPL / OPLL 系チップの出力が、揃える前（素の v1.1.4 / v1.5.9 の挙動）と比べて、
ネイティブレート（`clock / 72`）以外で変わる（§5.3）。`SSG` `SCC` `SCCP` `DCSG` は変換器が
別物で、影響しない。

**前提**: submodule の emu8950 が v1.2.2 以降、emu2413 が v1.6.3 以降であること（いまは
v1.2.3 / v1.6.4）。古い版に
戻すと、そのコアのチップの位相ずれが戻る。そのとき api_test が落ちる項目は §5.2 の表
（位相合わせ）にある。

### 3.6 SSGS

**コア**: `src/y8960/Y8960SsgsCore.{c,h}`。emu2149 v1.42 のフォークで、公開記号は
`PSG*` → `Y8960SSG*` に改名してある。1 インスタンスが SSG 1 系統（YM2149 + チャンネルごとの
音量と定位）にあたる。

仕様は Y8960 の仕様書（2026-10-15。§2）のシート ssg による。2026-10-16 までは YMZ705 の SSG 部
（4bit のパンポット、`20h` からが SSG-2、YMZ280B の分配則、`clock` はマスタークロック）として
作っていた。その形は §3.10 の「前の形」に残した。

素の emu2149 との差（**確認済み**: 2026-10-16 に、改名を戻して submodule（`441f3dc`）の
`emu2149.c/.h` と diff を取った。`.c` は冒頭のフォークの表記と下の表の関数・呼び出しの追加だけで、
`writeReg` は素の emu2149 と同じ）:

| 差 | 内容 |
|---|---|
| 音量と定位 | `Y8960SSG_setChannelVolume` / `Y8960SSG_setChannelPan`（チャンネル 0-2）。`ch_volume[3]`・`pan[3]` と、2 つを掛けた L/R の倍率 `ch_gain[3][2]` を持つ。`writeReg` は素の emu2149 と同じく `00h`-`0Fh` だけを受ける |
| 則 | 音量は 値 / 128（128 を超える値は 128）。定位は `Y8960Pan.h`（§3.10） |
| リセット | 音量と定位を全チャンネル 128 にする。`Y8960SSG_new` でも同じ（素の emu2149 の `PSG_new` はリセットを呼ばないため） |
| `Y8960SSG_calcStereo` | チャンネルごとに倍率を掛けてから、`Y8960SSG_calc` と同じレート変換を L と R それぞれに掛ける。`Y8960SSG_calc`（mono）は音量も定位も掛けない |

**変えていないもの**: 音量表（YM2149 の 32 段）、ノイズ、エンベロープ、ナイキストを超える
トーンを止める処理（`freq_limit`）、`0Eh` / `0Fh` を覚えるだけで音に効かないこと。

**直流**: emu2149 は無音のチャンネルを 0 で出し、音量表の最小値も 0 なので、無音時の
レベルは 0 である（**確認済み(読解)**: `voltbl[0][0] = 0`、`update_output` の `ch_out[i] = 0`）。
定位を掛ける前に無音時レベルを引く処理は要らない。発音中の直流はそのまま残る（`SSG` チップと同じ）。

**ノイズ**: emu2149 の LFSR は、blueMSX-plus_Y8960 が §9.11 で上流から移植した修正と同じ
マスク `0x24000` をすでに使っている（**確認済み(読解)**: `update_output`）。

**エンジン側**:

- 2 個のコアを持つ。`reg < 20h` のとき `reg >> 4` で系統を選び、`reg & 0Fh` を渡す
- `20h`-`2Fh` は 4 個ずつ SSG-1 の音量、SSG-2 の音量、SSG-1 の定位、SSG-2 の定位で、
  `(reg >> 2) & 1` が系統、`reg & 8` が定位か音量か、`reg & 3` がチャンネル。各組の 4 個目
  （`23h` `27h` `2Bh` `2Fh`）と `30h` 以降は未接続で捨てる
- `clock` は SSG の動作クロックで、そのままコアに渡す（§3.5）
- 出力は 2 系統の `calcStereo` の和。部位は持たない（2 系統は足し合わせて 1 つの
  ステレオ出力にしている）
- 内蔵のレート変換を使う（`Y8960SSG_setQuality(unit, 1)`。`SSG` チップと同じ）

**読み出し・GPIO・LED**（`0Eh` / `0Fh`、`1Eh` / `1Fh`。`1Fh` の下位 4bit が基板の LED）:
無し（FmEngineApi に読み出しが無い）。書いても音に効かない。

### 3.7 外部メモリの割り当て（FmEngine_SetMemoryEx）

FMEngineTest の `docs/FmEngineApi.md`「外部メモリ (任意)」「外部メモリの割り当て (任意)」を
実装した。割り当ては `98d73ec`、名前での指定は `0c22d67`。

**名前**: 外部メモリは名前の文字列で指定し、`FmEngine_GetMemoryCount` /
`FmEngine_GetMemoryName` で列挙する（`0c22d67`。それまでは番号 `FmMemoryType` と
`FmEngine_GetMemorySize`）。名前の表（`kAdpcmMemories`）の添字が `index` で、そのまま
`ChipEntry::mappings` と emu8950 の `memory[]` の添字になる（0 が `ADPCM_B`、1 が
`ADPCM_B_ROMMODE`）。`OPL2EX` は表の先頭の 1 個だけを持つ。名前は `strcmp` で全体を比べる。

**`FmEngine_SetMemory`**: チップ自身が持つ 256KB の先頭へ複製する（256KB を超える分は
捨てる）。`data` には書き込まない（仕様 `e3632cc`。**確認済み(読解)**: `memcpy` の読み側に
しか使っていない）。`data` が null で `size` が 0 でなければ `FM_ERR_INVALID_ARG`、`size` が
0 なら何もせず `FM_OK`（仕様は定めていない）。`Y8950` の `ADPCM_B_ROMMODE` は ROM モードの
メモリへ入る（§3.5）。

**OPL2EX**（仕様どおり）:

- 割り当ては `ChipEntry::mappings[0]` に持ち、コアには割り当ての表（§3.2）として渡す。
  RAM は書ける割り当て、ROM は書けない割り当てとしてブロックをそのまま参照する
  （ROM の複製は仕様で「してよい」であって、しなくてもよい）
- 割り当てが無い間は、`SetMemory` が書き込む 256KB を 0 番地からの 1 つの割り当てとして渡す
- `ADPCM_B_ROMMODE` は `FM_ERR_INVALID_ARG`（ROM モードのメモリが無い。§3.2）
- 番号で指定していた頃、仕様書の表に OPL2EX の行は無く、足す必要も無いとされた
  （2026-10-02 ユーザー回答）。OPL2EX のメモリは Y8950 / YM2608 と同じ ADPCM-B であり、
  メモリの共有も外部回路の作り方しだいで Y8950 / YM2608 でもありうるもので、OPL2EX 特有の
  機能ではない。名前での指定になってからの扱いは §6.7

**Y8950**（制限付き。2026-10-02 ユーザー決定）:

emu8950 は RAM モードのメモリ（`memory[0]`）と ROM モードのメモリ（`memory[1]`）を別々の
256KB の配列に持ち、`08h` の bit0 で `wave` をどちらかに向けて添字で直接読み書きする
（**確認済み(読解)**: `emuadpcm.c`）。番地ごとに割り当てを引く口を挟めないので、配列の
ポインタを差し替えて表す（`applyY8950Memory()`）。

| そのメモリの割り当て | `memory[n]` の向け先 |
|---|---|
| 無し | emu8950 自身の配列（`SetMemory` の書き込み先） |
| RAM がある | そのブロック。`base` 0 で 256KB 以上のものしか受け付けない |
| ROM だけ | 0 で埋めた 256KB の配列に各ブロックを複製したもの |

同じ RAM ブロックを複数の Y8950 に割り当てれば共有になる（各チップの配列が同じブロックを
指す）。分割はできない（部分的な RAM を受け付けないため）。

- 再生中の `wave` も同じ配列を指すので、差し替えた配列を指していたら一緒に差し替える
- `OPL_delete` は `memory[]` を解放するので、破棄の前に emu8950 自身の配列へ戻す
- `SetMemory` は emu8950 自身の配列へ直接複製する（割り当て中に `OPL_writeADPCMData` を
  呼ぶと、呼び出し側のブロックや複製に書いてしまうため）。`ADPCM_B` は `memory[0]`、
  `ADPCM_B_ROMMODE` は `memory[1]` だった配列へ入る

**Y8950 で仕様と食い違うところ**（**確認済み(読解)**。試験はしていない）:

- ROM の割り当てと割り当ての無い番地へのチップの書き込みを捨てられない。複製の配列に
  書き込まれ、次に割り当てを変えるまで読める（呼び出し側のブロックは書き換わらない）
- emu8950 は ROM モード中も `0Fh` からの書き込みを `wave`（ROM モードのメモリ）に入れる。
  FMEngineTest の CHANGELOG によれば実機は ROM モードでは書き込まない。emu8950 の挙動で、
  `SetMemoryEx` で変わるものではない

**見送った案**:

- Y8950 も OPL2EX のフォークで動かして仕様どおりにする（チップ種別と ROM モードの
  メモリをフォークに戻す）。理由: ユーザーが素の emu8950 のままを選んだ
- Y8950 の部分的な RAM を、毎回の `Generate` の前後で配列とブロックの間を写して表す。
  理由: 仕様の「その場で読み書きする」に当たらない。`FM_ERR_UNAVAILABLE` を返せばよい

**共通**:

- 範囲は 64bit で比べる（`base + size` が 32bit を超えても重なりを取り違えない）
- `write_mutex` を取る（仕様は「ストリーム開始前に呼ぶ」だが、取って困ることは無い）
- `FmEngine_Write` はその場でチップに書くので、仕様の RAM の約束 2・3（`Write` の前に
  書いた値が見える、`Write` で書いた値は次の `Generate` が戻るまでに入る）は満たす
  （**確認済み(読解)**: `chipWrite` が `write_mutex` の中でコアに書く。試験でも 0Fh の
  書き込みが `Write` の直後にブロックへ入っていることを見ている）

### 3.8 クロック

`FmEngine_AddChip` は `clock` = 0 に `FM_ERR_INVALID_ARG` を返す。エンジンは既定の
クロックを持たない（仕様 FMEngineTest `a17c372`。`kChipTable` から既定値の列を外した）。

- 判定は名前の照合より前に置いた。未知の名前で `clock` = 0 のときは
  `FM_ERR_INVALID_ARG` になる（仕様はこの組み合わせを定めていない。YMEngine `f44ff0f` と
  EPSGemuEngine `7cd1e8a` が同じ順。**確認済み(読解)**）
- 外す前の既定値は `SSG` が 2000000、他の 13 チップが 3579545。同じ値を渡せば出力は
  変わらない（§5.5）
- Y8960 の OPLL-EX / OPL2-EX のクロックは 3.579545MHz（MSSX `hardware.md`）。`SSGS` の
  `clock` の意味は §3.5
- README の対応チップ一覧は、既定のクロックの列をやめてネイティブレートを式で書いた
  （EPSGemuEngine `7cd1e8a` の README と同じ形）

**やり直しの値段**: 既定値を戻すなら `kChipTable` に列を足して `createChip` の 1 行。
仕様に反するので、戻すのは仕様が変わったときだけ。

### 3.9 FmEngine_GetNativeRate の廃止

`FmEngine_GetNativeRate` を消した（仕様 FMEngineTest `831947d`。必須のシンボルは 12 個から
11 個になった）。エンジンの中でこの値を使っていた箇所は無く、返すためだけの関数
（`nativeRate()`）と、そのためだけに持っていた `ChipEntry::sample_rate` も消した。

- 返していた値: `SSG` は `clock` / 8、OPL / OPLL 系（`OPL2EX` / `OPLLEX` を含む）は
  `clock` / 72、`SCC` / `SCCP` は `clock` / 2、`DCSG` は `clock` / 16、`SSGS` は SSG の
  動作クロック / 8。README の対応チップ一覧の「ネイティブレート」の列に同じ式がある
  （`SSGS` は 2026-10-16 から `clock` が SSG の動作クロックなので、README は `clock` / 8）
- README の列は、コアが内部で音を作るレートの説明として残した（2026-10-03、ユーザーに
  断った上で）。OPL / OPLL 系では、エンジンのサンプルレートをこの値にするとレート変換を
  通らない（§3.4、§5.3）。**この列を裏づける試験は無くなった**（消した試験 3 項目は関数の
  戻り値を見ていただけで、コアのレートを測ってはいなかった）。式は各コアのソースと合う
  （**確認済み(読解)**: emu2413 / emu8950 は `f_inp = clk / 72`、emu2212 は `sccstep` が
  `clk / 2`、emu76489 は `sngstep` が `clk / 16`、emu2149 とそのフォークは
  `psgstep = rate * 8` で、1 出力サンプルあたり `clk / (rate * 8)` 回の内部更新になる）
- `FmEngine_GetNativeRate` がエクスポートに残っていると、`api_test` は読み込みの段階で
  失敗にする（§5.1）。仕様は残したエンジンも準拠としているが、本エンジンは消すと決めた
  ので、戻ってきたら気づけるようにした

**外から見える影響**: `831947d` より前の FMEngineTest は、この DLL をロードできない
（§0）。アプリケーション（FitomEmuIF、Y8960Sequencer、FITOM_X、FITOMApp）は呼んでいない
（FMEngineTest の CHANGELOG による。本リポジトリでは確かめていない）。

### 3.10 Y8960 の仕様書（2026-10-15）への追随

2026-10-16 にユーザーから受け取った仕様書（§2）と、それまでの実装の差を埋めた。

| ブロック | 仕様書で変わったこと | 本リポジトリ |
|---|---|---|
| SSG | YMZ705 の SSG 部ではなく自作の Dual SSG。SSG-1 が `00h`-`0Fh`、SSG-2 が `10h`-`1Fh`。チャンネルごとの音量（`20h`-`22h` / `24h`-`26h`、0-128、既定 128）と 8bit の定位（`28h`-`2Ah` / `2Ch`-`2Eh`、1 が左端・128 が中央・255 が右端、既定 128） | §3.6 |
| OPLL-EX | ch0-8 の 8bit の定位 `50h`-`58h`（同じ値の意味、既定 128）。`40h`-`48h` のバンクは変わらない | §3.1 |
| OPL2+ADPCM | `07h` の SPOFF を廃止。`05h` `06h` `0Dh` `0Eh` `15h`-`1Ah` も廃止 | §3.2 |
| SCC、MemoryMappedIO | エンジンの対象外（§1 のスコープ外） | 変えていない |

**定位の則**: `src/y8960/Y8960Pan.h` の `Y8960_panGain` に 1 つだけ置き、2 つのフォークが
使う。等パワー（L = cos θ、R = sin θ、θ = (値 − 1) / 254 × 90°）と 0 を中央とすることは
2026-10-16 のユーザー決定。中央の倍率は 0.707 なので、定位を書かない `SSGS` / `OPLLEX` の片側の
レベルは、素の `SSG` / `OPLL` の 0.707 倍になる。左端（1）の倍率はちょうど 1.0 で、試験は
これを使って素のチップとビット一致を見る。`OPLLEX` は 4.12 固定小数点に丸める（中央は 2896 / 4096）。

**前の形**（2026-10-16 まで。YMZ705 の SSG 部として作っていたもの）: SSG-1 が `00h`-`1Fh`、
SSG-2 が `20h`-`3Fh`。各系統の `10h`-`12h` の下位 4bit がパンポットで、0 と 1 が左端・8 が中央
（両側とも全開）・15 が右端、片側だけを線形に絞る YMZ280B の則。`clock` はマスタークロックで、
SSG は 5.12MHz 未満なら 1/2、以上なら 1/3。`OPLLEX` は定位を持たず、`OPL2EX` は SP-OFF で無音に
なった。これらを前提にした変異 S1-S7（§5.2）と §6.5 の議論は、いまのコードには当たらない。

**同じ仕様を扱う他のリポジトリ**（2026-10-16 に各リポジトリの先頭を見た。**確認済み(読解)**）:
MSSX `05f30f6` の `hardware.md` は前の形（`13h` 未満が SSG1・`20h` 以上が SSG2、4bit の
パンポット）のまま。Y8960emu `40298b9`、openMSX_Y8960 `650989a7e`、blueMSX-plus_Y8960
`9aa8a0a7` は先頭のコミットが仕様書の日付より前。中身が前の形かは読んでいない。

## 4. 決定事項

### 4.1 OPL2EX は emu8950 をフォークする（2026-10-02）

依頼は「emu8950 ベースで実装、blueMSX-plus_Y8960 から切り出してよい」。blueMSX 側の
OPL2EX は GPL なので切り出せない（§2.1）。emu8950 は ADPCM と波形選択の両方をすでに
持っているので、チップ種別の分岐を外すだけで OPL2EX になる。

**前提**: 素の emu8950 を `Y8950` / `OPL` / `OPL2` に使い続けること。使わなくなれば
フォークせず改造で済む。

### 4.2 改名してフォークする（2026-10-02）

blueMSX-plus_Y8960 と同じ方式（公開記号に `Y8960` を前置）。OPLLEX はそのまま写し、
OPL2EX は `sed` で機械的に改名してから差分を当てた。**フォークは上流と行単位で近いまま
保つ**（改名を戻せば上流と diff が取れる）。

### 4.3 部位の 2 系統はパンで取り出す（2026-10-02）

emu2413 の内部の `ch_out[]` を直接読むと、レート変換器より前の値しか取れない。パンなら
公開 API だけで、変換器を通った 2 系統が得られる。§3.4 の位相合わせが前提。

### 4.4 SSGS は emu2149 をフォークし、パンをコアに入れる（2026-10-02）

emu2149 の内蔵レート変換は、3 チャンネルを足したモノラルにしか掛からない。チャンネルごとの
パンを変換より前に掛けるには、コアに手を入れるしかない。パンと分配則は YMZ705 の SSG 1 系統の
性質なのでコアに置き、2 系統への振り分けとクロックの分周はチップ全体の性質なのでエンジンに置いた
（EPSGemuEngine の `ymz_ssg_device` / `ymz705_device` と同じ分け方）。

2026-10-16 の仕様（§3.10）でも同じ分け方にした。音量と定位の値と則は 1 系統の性質なので
コアに置き、`20h`-`2Fh` の並び（2 系統の値が交互に並ぶ）はチップ全体の配置なのでエンジンが
読み解いてコアの関数を呼ぶ。

**前提**: 素の emu2149 を `SSG` チップに使い続けること。

### 4.5 定位の則は 1 か所に置く（2026-10-16）

`SSGS` と `OPLLEX` の定位は、仕様書で同じ書き方（1 / 128 / 255、既定 128）をされている。則を
`src/y8960/Y8960Pan.h` の 1 関数に置き、両フォークが使う。則を変えるときはここだけ直せばよい。
`OPLLEX` のレジスタはコアが受ける（バンクレジスタと同じ）。

**前提**: 2 つのブロックの定位が同じ則であること。仕様書が別々の則を定めたら分ける。

試験の作り: 新しいチップは、素のコアのチップに同じ書き込みをして出力を突き合わせる。

| 見たこと | 突き合わせ |
|---|---|
| OPL2EX の FM（波形選択あり / なし、リズム含む） | `OPL2` とビット一致 |
| OPL2EX の ADPCM | `Y8950` とビット一致 |
| `08h` b0 を立てても RAM から鳴る | 立てない場合とビット一致。`Y8950` では出力が変わる |
| `0Fh` 経由の書き込み | `SetMemory` と同じ出力 |
| チップごとに RAM が別 | 別チップに入れたデータは鳴らない |
| OPLLEX の 4 バンク | 音色 1 の出力が 4 バンクで互いに違う |
| チャンネル別のバンク | 2 チャンネル同時の出力 = 別々に鳴らした和（4 LSB 以内）、かつ「後勝ち」とは違う |
| 鳴っている途中のバンク切替 | 切り替えない場合と出力が違う |
| ユーザー音色 | バンク 0 と 3 でビット一致。`OPLL` との一致は「OPLLEX の定位」の行 |
| 部位ゲイン | メロディだけ = メロディだけを鳴らした `OPLL` とビット一致、リズムも同様。既定ゲインの出力 = 両者の和 |

111 項目のとき（`OPL2EX` の廃止されたレジスタの項目を足したあと。足す前の 14 変異は回し直して

追随の前（`a4469ae` のソース。emu8950 `30e89e2`）の DLL と追随後の DLL を、どちらも Windows の
x64 Release でビルドして比べた。比較に使ったプログラムはリポジトリに置いていない
（`tests/api_test.cpp` の部品を取り込み、場面ごとの出力をファイルに書き出すもの）。

**DLL を直接呼ぶ比較**: 46 通りの書き込みを 48000 / 44100 / 49715 / 49716Hz で 0.5 秒ぶん鳴らし、
出力をバイトで比べた（184 通り。どれもピークが 1e-3 以上）。

- 46 通りの内訳: 14 チップそれぞれの発音。`Y8950` と `OPL2EX` のそれぞれで、ADPCM の繰り返し
  再生、繰り返し再生 + FM、1 回だけの再生、繰り返し再生の 1000 フレーム目で `07h` = 01h / 00h /
  98h。OPLL 系 5 チップのそれぞれで、音色 1〜9 を 9 チャンネルで鳴らして途中でキーオフ
  （サステインあり / なし）、途中で音量を変える、ユーザー音色と音色 11〜15 から途中でリズム。
  49716Hz は、上流の CHANGELOG が「3.58MHz で 49716 にすると変換器が外れる」と書いているので足した
- **120 通りがバイト一致。食い違う 64 通りは、`Y8950` `OPL` `OPL2` `OPL2EX` の 16 場面 × 4 レート
  すべて**で、ほかのチップは 1 つも食い違わない
- 48000 / 44100Hz の差は時間とともに増える（`OPL2` の FM で、最初の 2000 フレームの最大差 133
  LSB が 0.5 秒の手前で 529 LSB。ピークは 4005 LSB）。フォークの `f_inp` だけを `clk / 72` に
  戻した版（§5.2 の H2）でも、`OPL2EX` は同じだけ増える。増える分は出力のタイミングを整数で
  正確にした変更から来ている（**推測**: 位相の丸めの差は一定の 1/512 サンプルで時間とともに
  増えず、`f_inp` は H2 で除いた。タイミングだけを戻した版は作っていない）
- 49715Hz では、追随後の出力が追随前の出力を 1 サンプル進めたものと一致する（`OPL2` の FM で、
  20000 サンプルにわたって差 0）。変換器はどちらも働かない。追随後は `out_step`（3579545）が

  `inp_step` に積もる間隔からの計算。0.5 秒の比較の範囲には入らない）
- 49716Hz では、追随前は変換器が働き、追随後は働かない（上流の CHANGELOG のとおり。読解）

**mono 経路との比較**: 追随後の emu8950 とフォークを直接リンクし、FM を鳴らして mono の
`OPL_calc` / `Y8960OPL_calc` と `calcStereo` の L・R を比べた。emu8950 の 3 種別とフォークの

非 0 のサンプルが 23977 以上）。

**試験**: api_test は 97 項目すべて通る（Windows の `ctest`）。フォークを写さずに submodule だけ

### 6.2 OPL2EX 2 個でサンプル RAM を共有させるか — **決着。`FmEngine_SetMemoryEx` で共有する（2026-10-02）**

ユーザーが FmEngineApi を改定し（FMEngineTest `98d73ec`）、RAM のブロックを呼び出し側が
持って複数のチップに割り当てられるようになった。実装は §3.7。以下は決着前の材料。

実機は 2 回路で 256KB を分け合い、起動時は共有（両フォークと MSSX の文書。
**確認済み(読解)**）。本エンジンはチップごとに別の RAM を持つ。`0Fh` 経由で片方の回路から
書いたサンプルを、もう片方で鳴らすソフトは、本エンジンでは鳴らない。

**値段**: コアは窓を外から受け取る形にしてあるので、エンジン側で RAM の持ち主と窓の
割り当てを決めるだけで済む。決めるべきは外から見える部分（どのチップどうしを組にするか、
`SetMemory` がどこに書くか）で、FmEngineApi に口が無い。

**Y8960emu（`eb0dd4e`）のやり方**（**確認済み(読解)**: `src/FmChip.h` の
`MemoryYmfmInterface`、`src/opl2ex.cpp` の `write_data`。動かしてはいない）:

- 共有のための仕組みは無い。1 回路 = 1 チップ
- `FmEngine_SetMemory` はコピーせず、呼び出し元のポインタを覚える。読み出しはそのバッファを
  直接見る。**2 チップに同じバッファを渡せば、再生は結果として共有になる**（README と設計書に
  共有の手段としての記載は無い）
- そのバッファは書き込み不可の扱いで、書ける領域を作る `allocMemory` はどこからも呼ばれて
  いない。`07h` の REC / MEMORY DATA と `0Fh` による書き込みは捨てられる。`SetMemory` の前は
  読み出しが 0
- 本エンジンとの差: 本エンジンの `SetMemory` はチップ自身の 256KB へのコピーで、`0Fh` 経由で
  書ける（自チップの RAM だけ）。FmEngineApi の仕様（「data の寿命は呼び出し元が管理する
  こと」）はどちらの作りも許す

**案**（未決）: `SetMemory` を Y8960emu と同じ参照にすれば、同じバッファを渡すだけで共有に
なる。ただし受け取るデータは `const` なので、そのままでは `0Fh` 経由の書き込みと両立しない。
書き込みも共有したいなら、API の外に共有の手段が要る。

**見送った案**: 同じエンジン内の `OPL2EX` を追加順に 2 個ずつ組にして共有させる。
理由: 組み方が暗黙になり、1 個だけ使う利用者の `SetMemory` の意味が変わる。
Y8960emu とも振る舞いが分かれる。

- **フォークは旧い変換器のまま。** `OPLLEX` は emu2413 v1.5.9、`OPL2EX` は emu8950 v1.1.4 の
  変換器に位相の 2 行を足したもの。`OPL2EX` の `reset_rate_conversion_params` には `clk / 72` の
  切り捨てが残っている（**確認済み(読解)**）。`OPLLEX` は `72.0` で割っており、切り捨ては無い
- **submodule だけ上げると、試験が 4 項目落ちる見込み。** フォークと素のコアのビット一致を
  見ている項目（`OPLLEX` のユーザー音色と `OPLL`、`OPL2EX` の FM と `OPL2` の 2 項目、`OPL2EX` の
  ADPCM と `Y8950`）（**推測**: 試験は 48000 Hz で変換器が働き、片側だけ変換器が変わるため。
  走らせていない）

選択肢と値段:

| 案 | すること | 値段 |
|---|---|---|
| A | 2 つを上げ、フォーク 2 つにも同じ変換器の変更を入れる（`OPL2EX` には内部レートの修正も） | フォークごとに、上流の `.c` の差分（emu2413 +61 -50、emu8950 +62 -48）と `.h` の差分を写す。前後の出力比較、試験の判別力の確認、README の「元にしたコア」、§3.1・§3.2・§5 |

| C | 見送る | なし。上流との差が開く |

## 7. 見送った提案

- **blueMSX-plus_Y8960 の OPL2EX（openMSX 由来）を写す**。理由: GPL（§2.1）
- **emu2413 の内部の `ch_out[]` を読んで部位を分ける**。理由: レート変換器より前の値で、
  変換を自前で持つことになる（§4.3）
- **位相ずれを submodule で直す**。理由: submodule を改造しない規則。エンジン側で
  公開フィールドだけを使って揃えられた
- **SSGS を emu2149 のフォークなしで作る**（1 系統につき素の emu2149 を 3 個並べ、
  マスクで 1 チャンネルずつにして、それぞれにパンを掛ける）。理由: 同じ書き込みなら 3 個が
  同じ状態を辿ることに頼る作りで読み手が驚く。計算も 3 倍になる
- **SSGS のレート変換をエンジン側で行う**（emu2149 を `quality = 0` でネイティブレートで回し、
  `ch_out[]` を読む）。理由: ネイティブレートが整数にならない（1789772 / 8 = 223721.5）ので、
  1 呼び出し 1 ステップにならない
- **OPLL 系の位相合わせを DLL 越しに試験する**。理由: 同じ信号を L と R の両方に出す
  手段が API に無い。コア単体の計測（§5.3）で代えた
- **上流の issue を追跡する専用の文書を作る**（2026-10-03）。理由: 状態の正は GitHub にあり、
  文書に置けるのは控えだけ。状態は計測・修正案・回避策と一緒に読まないと次の行動が決まらず、
  分けると §9 と 2 箇所を合わせることになる。代わりに §9 の先頭に表と確かめ方を置いた。
  前提: 報告先が emu2413 / emu8950 の 6 件で、読むのが AI であること。件数や報告先が増えるか、
  人が一覧として読むようになったら見直す
- **`OPL2EX` の外部メモリの名前と、`Y8950` の `SetMemory` の `ADPCM_B_ROMMODE` の意味を、
  実装の前にユーザーに聞く**（2026-10-03）。CLAUDE.md は外から見える値を決める前に聞くと
  定めている。聞かなかった理由: どちらも既決の事項から 1 通りに決まると判断した（§3.5 の
  各行の「前提」）。その判断が外れていたときの値段は §3.5 の各行。コミットの前に報告して
  確認を求めることで代え、ユーザーは報告の内容を了承した
- **`api_test` で DLL のエクスポートの一覧を丸ごと仕様と突き合わせる**（2026-10-03）。
  理由: 一覧を取るには PE / ELF のエクスポート表を読むことになる。仕様から外れた 2 関数が
  残っていないことだけを試験に入れ、一覧は `dumpbin` / `nm` で見た（§5.1）。前提: 関数の
  増減は仕様の改訂のときにしか起きず、そのたびに一覧を見ること
- **変更前の既定のクロックを README に残す**（2026-10-03）。理由: README は現在の仕様を
  書く文書で、エンジンはもう既定値を持たない。値は §3.8 に置いた
- **`OPLLEX` を、メロディとリズムに振り分けずに鳴らす形に単純化する**（2026-10-03）。
  部位を出さないと決まったので、振り分けて混ぜ直す経路は要らなくなった。理由: 出力が
  最大 1 LSB 変わる（§6.1）。依頼は部位を出さないことで、出力を変えることではなかった。
  値段は §6.1
- **`clock` がコアに届いていることを、全チップで見る試験を足す**（2026-10-03）。`SSG` と
  `SSGS` 以外では見ていないと分かった（§5.2 の C1）。理由: `FmEngine_GetNativeRate` の
  廃止で生じた穴ではなく、依頼の外。値段は、`SCC` / `SCCP` / `DCSG` を鳴らすレジスタ列を
  試験に足して 1 項目（クロックを変えると出力が変わること）と、C1 で落ちることの確認
- **`OPL2EX` のフォークの `Y8960OPL_calcStereo` に、上流の #5 と同じ修正（`timer` を戻す
  2 行）を入れる**（2026-10-08）。理由: 依頼の前に提示して了承されたのは ADPCM の 2 箇所で、
  これは入っていなかった。入れても出力は変わらない（エンジンの `calcStereoAligned()` が
  すでに揃えている。素の emu8950 では入った状態で出力が同じ。§5.7）。入れると、エンジンの
  位相合わせが効いていることを api_test が見る手段が無くなる（いま見ているのは `OPL2EX` を
  通してだけ。§5.2 の M7 の回し直し）。値段: フォークに 2 行。入れるなら、OPLL 系の位相合わせを
  見る別の手段が要る
- **素の emu8950 の 3 チップ（`Y8950` `OPL` `OPL2`）を `calcStereoAligned()` から外す**
  （2026-10-08）。v1.2.2 ではコア自身が揃えるので、外しても出力はビット一致する（§5.7）。
  理由: 依頼の外。掛けたままでも正しく、OPL 系 4 チップが同じ経路を通る。値段: 1 行と
  コメント。前提: emu8950 の `OPL_calcStereo` が `timer` を「L の前の値に戻す」形のままで
  あること。チャンネルごとの `timer` を持つ形などに変わったら、掛けたままでは誤りになりうる
  （submodule を上げるたびに §5.7 の mono 経路との比較をやり直す）

上の 2 件は、同じ日のうちに見送りをやめて実施した（§3.4、§5.9）。見送ったときの理由が
成り立たなくなったため: emu2413 も直って位相合わせが要るのがフォークだけになり、ユーザーから
「OPLLEX に展開する必要があればそれもやって」と指示があった。フォークに修正を入れると
エンジンの位相合わせはどのチップにも要らなくなるので、取り除いた。「api_test が見る手段が
無くなる」という懸念は、修正を外した版で試験が落ちることで解けた（§5.2 の F1・F2）。

**この判断の範囲**: 指示は `OPLLEX` への展開で、`OPL2EX` のフォークの `calcStereo` と
エンジンの `calcStereoAligned` の除去は、こちらで合わせて行った。`OPLLEX` だけに入れると、
片方のフォークだけが直り、どのコアにも要らない回避策がエンジンに残る形になる。出力は
変わらない（§5.9）。戻す値段: この変更は 1 つのコミットに分けてあり、それを取り消せば
エンジンで揃える形に戻る。

- **Y8960 の仕様書（xlsx）をリポジトリに置く**（2026-10-16）。理由: 正本はユーザーの手元にあり、
  写すと版が 2 つになる。ファイルのプロパティに作成者の情報が入っている。必要な内容は §3.10 と
  §6.9 に写した。前提: 仕様書が公開の場所に置かれたら、そこを §2 で指す
- **`OPLLEX` の定位をエンジン側で `Y8960OPLL_setPanFine` を呼んで決める**（2026-10-16）。
  理由: 定位はチップのレジスタで、バンクレジスタと同じくコアが受けるのが §4.2 の作り
  （改名を戻せば上流と diff が取れる形）に合う。エンジンが受けると、`writeReg` とは別の経路で
  レジスタを読み解くことになる
- **`SSGS` の `20h`-`2Fh` の振り分けをコアに入れる**（2026-10-16）。理由: 2 系統の値が交互に
  並ぶ配置で、1 系統ぶんのコアには表せない（§4.4）

### 9.1 emu2413 / emu8950: `calcStereo` で L と R の補間位置がずれる

- **報告**: emu2413#20、emu8950#5（2026-10-03）。emu8950 の再現は下の「測り直し」の 1 音
- **上流の対応**（2026-10-08 に確認）: emu8950#5 は PR #10 で直り、v1.2.2（`30e89e2`）に入った。
  差分は下の修正案の emu8950 側と同じ 2 行（`timer` を覚えて R の前に戻す）。
  emu2413#20 は、メンテナから「`OPLL_calcStereo()` は長く手を入れておらず、ほかの issue と
  合わせて順に対応する」という返事があったあと、同じ日のうちに PR #21 で直って閉じ、
  v1.6.3（`83254be`）に入った。差分は下の修正案の emu2413 側と同じ 2 行。本リポジトリの
  submodule も同じ日に上げた（§5.8）
- **対象**: digital-sound-antiques/emu2413 `11676f6`（v1.5.9）の `emu2413.c`
  `OPLL_RateConv_getData` / `OPLL_calcStereo`。digital-sound-antiques/emu8950 `c27078c`
  （v1.1.4）の `emu8950.c` `OPL_RateConv_getData` / `OPL_calcStereo`
- **起きること**: 出力レートが `clock / 72` と違ってレート変換器が働くとき、`calcStereo` の
  L と R が別々の位置で補間される。パンが中央でも L ≠ R になり、どちらも mono の `calc` の
  出力と一致しない
- **原因**: 変換器の `timer` は全チャンネルで 1 つで、`getData` を呼ぶたびに `f_ratio` だけ
  進む。`calc` は 1 出力サンプルにつき 1 回呼ぶので正しいが、`calcStereo` は L と R で 2 回
  呼ぶので、1 出力サンプルで 2 回進む。`getData` の直前のコメント「this function must be
  called f_out / f_inp times per one putData call」も、チャンネルごとに 1 回ずつの意味で
  書かれていない
- **計測**（**確認済み**）: 48kHz、0.5 秒。パンは既定（中央）

  | コア | 鳴らしたもの | ピーク | max \|L−R\| | max \|L − mono\| |
  |---|---|---|---|---|
  | emu2413 | メロディ 1 音 + リズム 5 音 | 17401 | 10129 | 10298 |
  | emu8950 (YM3812) | 6 音 + リズム 5 音、波形選択なし | 6320 | 4658 | 4656 |

  単位は 16bit の LSB。mono は同じ書き込みをした別インスタンスの `OPLL_calc` / `OPL_calc`

### 9.2 emu8950: Y8950 以外の種別にすると ADPCM のメモリが解放されない

- **報告**: emu8950#6（2026-10-03）
- **上流の対応**（2026-10-08 に確認）: PR #11 で直り、v1.2.2（`30e89e2`）に入った。差分は下の
  修正案と同じ 1 行。メンテナの返事は「重大な不具合なので直す」
- **対象**: emu8950 `c27078c` の `emu8950.c` `refresh_adpcm_object`
- **起きること**: `OPL_new` は種別 0（Y8950）で ADPCM を作る。その後 `OPL_setChipType` で
  1（YM3526）か 2（YM3812）にすると、ADPCM の RAM と ROM（各 256KB）が解放されずに残る。

- **原因**: `free(opl->adpcm)` で構造体だけを解放し、`OPL_ADPCM_delete` を呼んでいない
- **計測**（**確認済み**）: `OPL_new` → `OPL_setChipType(opl, 2)` → `OPL_delete` を 200 回で、
  プロセスの PagefileUsage が 1.2MB → 103.1MB。`OPL_setChipType` を呼ばない（Y8950 のまま）
  200 回では 103.1MB → 103.6MB。2026-10-03 の測り直し（順序を逆にして Y8950 を先に回した）:
  Y8950 のまま 200 回で 1.1MB → 1.1MB、YM3812 にして 200 回で 1.1MB → 102.4MB
- **修正案**（**確認済み**: 写しに当てて同じ計測をやり直し、YM3812 の 200 回で 1.3MB → 1.0MB。
  2026-10-03 の測り直しでは 1.1MB → 1.1MB）

  ```diff
  --- emu8950.c  refresh_adpcm_object
       if (opl->adpcm != NULL) {
  -      free(opl->adpcm);
  +      OPL_ADPCM_delete(opl->adpcm);
         opl->adpcm = NULL;
  ```

- **本リポジトリ側**: submodule を v1.2.2 に上げた（2026-10-08）。それまでは `OPL` / `OPL2`
  チップを 1 個足すごとに 512KB がプロセスの終わりまで残っていた。上げたあとは残らない
  （**確認済み**: DLL 越しに、チップ 1 個のエンジンを作って壊すのを 200 回繰り返し、
  プロセスの PagefileUsage を見た。追随の前の DLL は `OPL` で 1.8MB → 103.1MB、`OPL2` で

  前後とも増えない）。OPL2EX のフォークにはこの関数が無い

### 9.3 emu8950: ADPCM が再生を止めたあとも最後の復号値を出し続ける

- **報告**: emu8950#7（2026-10-03）。実機については「未確認。参考として ymfm は 0 に戻す」と
  書いた
- **上流の対応**（2026-10-08 に確認）: PR #12 で直り、v1.2.2（`30e89e2`）に入った。差分は下の
  修正案と同じ 3 行（`OPL_ADPCM_calc` で `play_start` が 0 なら 0 を返す）。実機の挙動に
  ついての返事は無かった
- **発端**: 2026-10-03 にユーザーから「再生を停止しても DC 成分を出し続けているという指摘が
  あった（実測済み）」と伝えられた。この実測はエミュレータの出力を測ったもので、実機との比較では
  ない（ユーザーの回答）。下の計測は、その実測とは別に本リポジトリでやり直したもの
- **対象**: emu8950 `c27078c` の `emuadpcm.c` `calc` / `OPL_ADPCM_calc`
- **起きること**: ADPCM の再生が止まったあと、`OPL_ADPCM_calc` が最後の復号値に音量（`12h`）を
  掛けた値を返し続ける。`OPL_calc` / `OPL_calcStereo` の出力に直流が乗り、次の START まで
  消えない。止まり方が「停止アドレスに届いた（REPEAT なし）」でも「`07h` = 01h（RESET）」でも
  同じ
- **原因**: `calc` は再生中かどうかによらず `(output[0] + output[1]) * reg[0x12] >> 13` を返す。
  `output[]` を 0 にするのは START と `OPL_ADPCM_reset` だけで、`play_start` を 0 に戻す 2 箇所
  （`update_stage` の終端、`writeReg` の RESET）は `output[]` に触らない
- **計測**（**確認済み**）: RAM に 256 バイトを置き、開始 0000h・停止 003Fh（255 バイト）、
  DELTA-N 8000h、音量 FFh、`07h` = A0h で再生。FM は鳴らさない。値は `OPL_calc` の戻り値

  | データ | 終端のあとの 1 秒 | さらに 9 秒後の 1 秒 | 再生 100 サンプル目で RESET、そのあとの 1 秒 |
  |---|---|---|---|
  | 全部 77h | 2039 | 2039 | 2039 |
  | 77h を 2 バイト、あとは 80h | 127 | 127 | 127 |
  | 擬似乱数 | −606 | −606 | −425 |

  レートは 49715Hz（レート変換なし）で、どの欄も最小と最大が同じ（一定値）。48000Hz では
  レート変換のリップルが乗るだけで同じ（全部 77h で 2043〜2049、平均 2046.09）。ADPCM の出力は
  音量 FFh で ±2040 が上限なので、全部 77h の 2039 は振り切った値がそのまま残っている。
  対照: START の前は 0、`OPL_MASK_ADPCM` でマスクすると 0、終端のあとで `07h` = 08h（SP-OFF）を
  書くと 0
- **再現**（49715Hz。`run` は `OPL_calc` を n 回呼んで最小と最大を出すだけの関数）:

  ```c
  static uint8_t pcm[256];
  OPL *opl = OPL_new(3579545, 49715);
  memset(pcm, 0x77, sizeof pcm);
  OPL_writeADPCMData(opl, 0, 0, sizeof pcm, pcm);
  /* 08h=00h 09h=00h 0Ah=00h 0Bh=3Fh 0Ch=00h 10h=00h 11h=80h 12h=FFh 07h=A0h */
  run(opl, 4972);    /* 再生。終端を越える（約 1020 サンプルで終わる） */
  run(opl, 49715);   /* min=2039 max=2039 */
  ```

- **修正案**（**確認済み**: `emuadpcm.c` の写しに当てて上の計測をやり直した。終端のあとも RESET の
  あとも 0（3 データ × 2 レート。48000Hz の RESET は、レート変換の過渡のあと 0）。再生中の
  サンプル列は修正の前後で一致した（`play_start` が 1 の間の `OPL_calc` の戻り値の FNV ハッシュ。
  3 データ × 2 レート、1019 / 983 サンプル））

  ```diff
  --- emuadpcm.c  OPL_ADPCM_calc
     if (_this->reg[0x07] & R07_SP_OFF)
       return 0;

  +  if (!_this->play_start)
  +    return 0;
  +
     return calc(_this);
  ```

  `play_start` を 0 に戻す箇所で `output[]` を 0 にする形は採らなかった。終端では `update_stage` が
  1 を返して `update_output` が続けて走るので、`update_stage` の中で 0 にしても上書きされる
  （**確認済み(読解)**）
- **実機でどうなるか**: **未確認**。データシートも実機の計測も見ていない。参考として
  aaronsgiles/ymfm `81aec25`（BSD-3-Clause）の `src/ymfm_adpcm.cpp` は、終端（REPEAT なし）と
  RESET の両方でアキュムレータを 0 にする（**確認済み(読解)**: `adpcm_b_channel::clock` と
  `adpcm_b_channel::reset`）。実機の出力を測れば決まる
- **本リポジトリ側**: `Y8950`（素の emu8950）と `OPL2EX`（フォークの `Y8960Opl2exAdpcm.c`。
  `calc` / `Y8960OPL_ADPCM_calc` / `07h` の処理が同じ形。**確認済み(読解)**）の両方に当たって
  いた。2026-10-08 に submodule を v1.2.2 に上げ、フォークにも同じ修正を入れて、両方とも
  止まると 0 を出すようになった（**確認済み**: DLL 越しに §5.1 の試験と §5.7 の比較。
  追随の前の DLL では同じ試験が落ちる。§5.2 の A1）。経緯は §6.6
